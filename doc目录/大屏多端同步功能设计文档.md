# 大屏多端同步功能设计文档

## 1. 概述

### 1.1 功能定位

为前台大屏展示增加**多端实时同步**能力。当多个浏览器同时打开同一大屏时，任意一端对窗口的操作（创建、拖拽、缩放、关闭）能实时反映到其他端，延迟低于 100ms。

```
端1 操作窗口 ──HTTP──▶ 后端 ──WebSocket──▶ 端2 看到变化
                                ──WebSocket──▶ 端3 看到变化
```

### 1.2 方案

**流程：端1 操作 → HTTP 写后端 → 后端通过 WebSocket 推送给所有端**

```
端1 拖拽窗口
  │
  ├── 1. 自己先更新 DOM
  ├── 2. HTTP PUT /screen/{screenId}/window/{windowId}  ──▶ 后端写库
  │                                                          │
  │                                                          └── 广播给所有订阅端 → 各端按 windowId 更新对应窗口
  │
  └── 3. HTTP 失败 → 回退 DOM
```

> 各端收到 WebSocket 推送后只更新本地 DOM，不发起 HTTP 请求，避免死循环。


## 2. 接口

### 2.1 接口汇总

| 接口 | 说明 |
|------|------|
| `ws://host:8085/ws/screen` | WebSocket 连接，订阅大屏后接收实时推送 |

### 2.2 接口详情

#### 2.2.1 大屏同步（WebSocket）

前端建立 WebSocket 连接，订阅指定大屏后，后端在窗口发生变更时主动推送消息到所有订阅端。


```
ws://host:8085/ws/screen?token=eyJhbGciOi...
```

**请求体：**

```json
{ "screenId": 1 }
```

**成功响应：**

```json
{
    "code": 1,
    "msg": null,
    "data": null
}
```

**失败响应：**

```json
{
    "code": 0,
    "msg": "Token 无效或已过期",
    "data": null
}
```

| 错误信息 | 场景 |
|------|------|
| Token 无效或已过期 | token 校验失败 |
| 大屏不存在: id=X | screenId 无效 |


## 3.广播消息

> 订阅成功后，当大屏发生变更时，后端主动推送消息给所有订阅端。

**广播示例（窗口更新）：**

```json
{
    "code": 1,
    "msg": null,
    "data": {
        "type": "WINDOW_UPDATED",
        "screenId": 1,
        "windowId": "win-abc123",
        "x": 500,
        "y": 300,
        "width": 800,
        "height": 600
    }
}
```

**广播消息类型：**

| type | 说明 |
|------|------|
| `WINDOW_CREATED` | 窗口被创建，带完整窗口信息 |
| `WINDOW_UPDATED` | 窗口被更新，带窗口位置大小 |
| `WINDOW_CLOSED` | 窗口被关闭，只带 windowId |
| `WINDOWS_CLEARED` | 窗口被清空 |
| `SCREEN_DELETED` | 大屏被删除 |

## 4. 要完成的功能（流程图）

### 4.1 连接与订阅

```
进入前台 → 选择大屏 → loadFrontendScreen(screenId)
  │
  ├── HTTP 加载大屏详情 + 窗口列表（快速渲染）
  │
  └── 建立 WebSocket 连接 → 发送 { screenId: 1 } → 等待消息
        │
        后续收到 WINDOW_xxx 消息 → 按 windowId 更新/创建/删除
```

### 4.2 窗口操作同步（以拖拽为例）

```
端1 拖拽窗口 → mouseup
  │
  ├── ① 乐观更新本地 DOM
  │
  ├── ② HTTP PUT /screen/{screenId}/window/{windowId} → 后端写库 → 广播 WINDOW_UPDATED → 所有订阅端收到 → 按 windowId 更新对应窗口
  │
  └── ③ HTTP 失败 → 回退 DOM
```

> 各端收到 WebSocket 推送后只更新本地 DOM，不发起 HTTP 请求，避免死循环。


### 4.3 窗口创建/关闭同步

```
端1 拖拽信号源开窗
  │
  └── HTTP POST /screen/{screenId}/window → 后端写库 → 广播 WINDOW_CREATED → 所有订阅端收到 → 创建窗口

端1 关闭窗口
  │
  └── HTTP DELETE /screen/{screenId}/window/{windowId} → 后端删库 → 广播 WINDOW_CLOSED → 所有订阅端收到 → 移除对应窗口
```

### 4.4 大屏删除

```
端1 删除大屏 → HTTP DELETE /screen/{id} → 后端广播 SCREEN_DELETED → 所有订阅端收到 → 清空画布
```

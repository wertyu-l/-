# 设备管理模块设计文档

## 1. 概述

设备管理模块是异构硬件设备管控系统的核心模块之一，负责管理系统中所有硬件设备的注册、查询、状态监控等功能。该模块通过数据库持久化存储设备信息，支持手动添加设备，并通过 `DeviceDriver` 统一接口获取设备实时信息与运行状态。

### 1.1 统一返回格式

沿用项目 `Result<T>` 封装（位于 `demo1-common` 模块）：

```json
{
  "code": 1,     // 1=成功，0=失败
  "msg": null,   // 失败时包含错误信息
  "data": {}     // 业务数据
}
```

## 3. 数据库设计

### 3.1 建表 SQL

文件位置：`demo1-server/src/main/resources/schema.sql`，在现有 USER 表建表语句之后追加。

```sql
CREATE TABLE IF NOT EXISTS DEVICE (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id       VARCHAR(100)  NOT NULL UNIQUE,   -- 设备唯一标识
    device_name     VARCHAR(200)  NOT NULL,           -- 设备名称
    device_type     VARCHAR(50)   DEFAULT 'REST',     -- 设备类型
    model           VARCHAR(100)  DEFAULT '',         -- 设备型号
    serial_number   VARCHAR(100)  DEFAULT '',         -- 序列号
    output_channels INT           DEFAULT 1,          -- 输出通道数
    max_resolution  VARCHAR(50)   DEFAULT '1920x1080',-- 最大分辨率
    base_url        VARCHAR(300)  NOT NULL,           -- 设备 REST API 基地址
    create_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP,
    update_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);
```

> `application.yaml` 中已配置 `spring.sql.init.mode: always`，启动时自动执行。`CREATE TABLE IF NOT EXISTS` 不会覆盖已有数据，与 USER 表无冲突。

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | 是 | 主键，自增 |
| device_id | VARCHAR(100) | 是 | 设备唯一标识，如 `device-001`，不可重复 |
| device_name | VARCHAR(200) | 是 | 设备名称，如 `REST-Node-01` |
| device_type | VARCHAR(50) | 否 | 设备类型，默认 `REST` |
| model | VARCHAR(100) | 否 | 设备型号，如 `DS-D2055NH-A` |
| serial_number | VARCHAR(100) | 否 | 序列号 |
| output_channels | INT | 否 | 输出通道数，默认 1 |
| max_resolution | VARCHAR(50) | 否 | 最大分辨率，默认 `1920x1080` |
| base_url | VARCHAR(300) | 是 | 设备 REST API 基地址，如 `http://localhost:8086` |
| create_time | TIMESTAMP | 否 | 创建时间 |
| update_time | TIMESTAMP | 否 | 最后更新时间 |

## 4. 数据模型

### 4.1 实体类 — SimDeviceInfo

位于 `demo1-common` 模块，存放纯设备描述信息，**不包含连接地址**（连接地址由 `DeviceEndpoint` 管理）：

```java
@Data
public class SimDeviceInfo {
    private String deviceId;       // 设备唯一标识
    private String deviceName;     // 设备名称
    private String deviceType;     // 设备类型
    private String model;          // 设备型号
    private String serialNumber;   // 序列号
    private int outputChannels;    // 输出通道数
    private String maxResolution;  // 最大分辨率
}
```

> **为什么没有 `baseUrl`？**  `baseUrl` 是管控系统才需要的连接信息，模拟设备不需要。应放在 `DeviceEndpoint` 中，由管控系统单独管理。

### 4.2 DeviceEndpoint — 设备连接信息

位于 `demo1-server` 的 `driver/` 包下，管控系统独有：

```java
@Data
public class DeviceEndpoint {
    private String deviceId;       // 设备唯一标识
    private String deviceType;     // 设备类型：REST / TLV
    private String baseUrl;        // REST 设备基地址
    private String ip;             // TLV 设备 IP（预留）
    private int port;              // TLV 设备端口（预留）
}
```

### 4.3 DevicePageDTO — 分页查询入参

放在 `demo1-server` 的 `common/` 包下：

```java
@Data
public class DevicePageDTO {
    private String deviceName;    // 设备名称（模糊搜索）
    private String deviceType;    // 设备类型（精确匹配）
    private Integer page;         // 页码
    private Integer pageSize;     // 每页数量
}
```

### 4.4 DevicePageVO — 分页返回 VO

放在 `demo1-server` 的 `common/` 包下。继承 `SimDeviceInfo` 并新增 `baseUrl`，解决分页响应需要返回 `baseUrl` 但 `SimDeviceInfo` 不含该字段的问题：

```java
@Data
@EqualsAndHashCode(callSuper = true)
public class DevicePageVO extends SimDeviceInfo {
    private String baseUrl;        // 设备 REST API 基地址
}
```

### 4.5 AddDeviceRequest — 添加设备请求 DTO

放在 `demo1-server` 的 `common/` 包下。前端提交的扁平 JSON 同时包含设备描述和 `baseUrl`，Controller 用此 DTO 接收后再拆分：

```java
@Data
public class AddDeviceRequest {
    private String deviceId;
    private String deviceName;
    private String deviceType;
    private String model;
    private String serialNumber;
    private int outputChannels;
    private String maxResolution;
    private String baseUrl;
}
```

### 4.6 设备状态 — SimDeviceStatus

位于 `demo1-common` 模块：

```java
@Data
public class SimDeviceStatus {
    private String deviceId;       // 设备唯一标识
    private boolean online;        // 是否在线
    private int windowCount;       // 当前窗口数量
    private String uptime;         // 设备启动时间
}
```

### 5.2 手动添加设备

```
POST /device
```

**请求体：**

```json
{
  "deviceId": "device-003",
  "deviceName": "REST-Node-03",
  "deviceType": "REST",
  "model": "DS-D2055NH-C",
  "serialNumber": "SN-REST-2024-0003",
  "outputChannels": 2,
  "maxResolution": "1920x1080",
  "baseUrl": "http://localhost:8086"
}
```

**必填字段：** deviceId、deviceName、baseUrl

**数据流向：**

1. Controller 接收请求体 → 映射为 `AddDeviceRequest`
2. Controller 拆分：设备描述字段通过 `BeanUtils.copyProperties` 拷到 `SimDeviceInfo`，`baseUrl` 单独取出
3. Controller 调用 `deviceService.addDevice(deviceInfo, baseUrl)`
4. Service 在事务中执行：`deviceMapper.insert(deviceInfo)` + `deviceMapper.insertBaseUrl(deviceId, baseUrl)`

**成功响应：**

```json
{
  "code": 1,
  "msg": null,
  "data": null
}
```

**失败响应（设备ID重复）：**

```json
{
  "code": 0,
  "msg": "设备ID已存在: device-003",
  "data": null
}
```

## 6. 设备接入说明

管控系统通过 `DeviceDriver` 统一接口调用设备，`baseUrl` 由 `DeviceEndpoint` 携带，不混入 `SimDeviceInfo`。

调用链路：

```
前端请求 /device/device-001/info
    │
    v
DeviceController
    │
    v
DeviceServiceImpl.getDeviceInfo("device-001")
    │
    +-- 1. 查数据库 → 拿到 SimDeviceInfo（设备描述） + base_url（连接地址）
    +-- 2. 构建 DeviceEndpoint(deviceId, deviceType, baseUrl)
    +-- 3. restDeviceDriver.getInfo(endpoint)
            │
            +-- HTTP GET http://localhost:8086/simulator/device/device-001/info
                    │
                    v
            模拟设备 (demo1-simulator :8086)

关键：SimDeviceInfo 只存设备描述，baseUrl 走 DeviceEndpoint，两清。
```

> 添加设备时，`baseUrl` 填写模拟设备地址，如 `http://localhost:8086`。

## 7. Service 层设计

### 7.1 DeviceService 接口

```java
public interface DeviceService {
    void addDevice(SimDeviceInfo device, String baseUrl);
    void deleteDevice(String deviceId);
    PageResult<DevicePageVO> getPage(DevicePageDTO pageDTO);
    SimDeviceInfo getDeviceInfo(String deviceId);
    SimDeviceStatus getDeviceStatus(String deviceId);
}
```

### 7.2 DeviceServiceImpl 核心逻辑

| 方法 | 逻辑说明 |
|-----|----------|
| addDevice | 校验 deviceId 是否已存在 → 设置默认值 → `@Transactional` 保证 `insert(device)` + `insertBaseUrl` 原子性 |
| deleteDevice | 根据 deviceId 查询 → 查不到则抛异常，查到了则删除 |
| getPage | 使用 PageHelper 分页 → `pageQuery` 返回 `Page<DevicePageVO>`（含 baseUrl）→ 转为 `PageResult` |
| getDeviceInfo | 查数据库获取 `SimDeviceInfo` + `baseUrl` → 构建 `DeviceEndpoint` → 调用 `DeviceDriver.getInfo()` |
| getDeviceStatus | 查数据库获取 `SimDeviceInfo` + `baseUrl` → 构建 `DeviceEndpoint` → 调用 `DeviceDriver.getStatus()` |

> **事务说明：** `addDevice` 需要加 `@Transactional`，保证 `insert(device)` 和 `insertBaseUrl` 两次写入要么都成功要么都回滚。
>
> `getDeviceInfo` 和 `getDeviceStatus` 通过 `DeviceDriver` 接口调用，后续接入 TLV 设备时只需替换 Driver 实现，Service 层代码无需改动。

## 8. Mapper 层设计

### 8.1 DeviceMapper 接口

| 方法 | 说明 |
|------|------|
| `insert(SimDeviceInfo)` | 插入设备描述字段 |
| `insertBaseUrl(deviceId, baseUrl)` | 单独插入 baseUrl |
| `deleteByDeviceId(deviceId)` | 按 deviceId 删除 |
| `findByDeviceId(deviceId)` | 按 deviceId 查询，返回 SimDeviceInfo（不含 baseUrl） |
| `getBaseUrl(deviceId)` | 单独查询 baseUrl |
| `pageQuery(DevicePageDTO)` | 分页查询，返回 `Page<DevicePageVO>`（含 baseUrl） |

### 8.2 ResultMap 设计

两个 ResultMap 分别服务于不同场景：

| ResultMap | 映射实体 | 包含 base_url？ | 用途 |
|-----------|---------|:---:|------|
| `BaseResultMap` | `SimDeviceInfo` | ❌ | `findByDeviceId` 查询 |
| `PageVOMap` | `DevicePageVO` | ✅ | `pageQuery` 分页查询 |

> `BaseResultMap` 不映射 `base_url`，因为 `SimDeviceInfo` 没有该字段。`PageVOMap` 映射 `base_url`，因为 `DevicePageVO` 继承 `SimDeviceInfo` 并增加了 `baseUrl` 字段。

### 8.3 关键 SQL 设计

- **分页查询**：`SELECT * FROM DEVICE`，动态条件拼接 `deviceName`（模糊搜索）+ `deviceType`（精确匹配），按 `id DESC` 排序
- **baseUrl 查询**：`SELECT base_url FROM DEVICE WHERE device_id = #{deviceId}`，只查单列，与 `SimDeviceInfo` 无关

## 9. Controller 层设计

### 9.1 DeviceController 路由规划

```java
@RestController
@RequestMapping("/device")
public class DeviceController {

    @Autowired
    private DeviceService deviceService;

    @PostMapping                        // 添加设备（接收 AddDeviceRequest，拆分为 SimDeviceInfo + baseUrl）
    @DeleteMapping("/{deviceId}")       // 删除设备
    @GetMapping("/page")                // 分页查询
    @GetMapping("/{deviceId}/info")     // 设备信息
    @GetMapping("/{deviceId}/status")   // 设备状态
}
```

> `addDevice` 接收 `AddDeviceRequest`，Controller 用 `BeanUtils.copyProperties` 将设备描述拷入 `SimDeviceInfo`，`baseUrl` 单独取出，一起传给 `deviceService.addDevice(deviceInfo, baseUrl)`。

### 9.2 异常处理

统一使用 `RuntimeException` 抛出业务异常，由 `Result.error()` 封装返回：

| 场景 | 异常信息 |
|------|----------|
| 设备ID重复 | `"设备ID已存在: xxx"` |
| 设备不存在 | `"设备不存在: xxx"` |
| 参数校验失败 | `"设备ID不能为空"` / `"设备名称不能为空"` |

## 13. 初始化数据

文件位置：`demo1-server/src/main/resources/data.sql`，在现有 USER 初始化数据之后追加。

对应模拟器默认注册的 `device-001` 和 `device-002`，`baseUrl` 指向 `http://localhost:8086`。

```sql
-- 使用 MERGE 避免重复执行时主键冲突
MERGE INTO DEVICE (device_id, device_name, device_type, model, serial_number, output_channels, max_resolution, base_url)
    KEY(device_id)
    VALUES ('device-001', 'REST-Node-01', 'REST', 'DS-D2055NH-A', 'SN-REST-2024-0001', 2, '1920x1080', 'http://localhost:8086');

MERGE INTO DEVICE (device_id, device_name, device_type, model, serial_number, output_channels, max_resolution, base_url)
    KEY(device_id)
    VALUES ('device-002', 'REST-Node-02', 'REST', 'DS-D2055NH-B', 'SN-REST-2024-0002', 2, '1920x1080', 'http://localhost:8086');
```

> **为什么用 `MERGE` 而不是 `INSERT`？**  `spring.sql.init.mode: always` 每次启动都执行 `data.sql`，用 `INSERT` 会在第二次启动时因主键冲突报错。H2 的 `MERGE INTO ... KEY(...)` 语句：存在则跳过，不存在则插入，安全可重复执行。

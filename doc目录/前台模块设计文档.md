## 1. 概述

### 1.1 模块定位

前台模块是异构硬件设备管控系统的**展示与交互层**，负责大屏展示、信号源管理和窗口交互。

**核心设计理念：** 整个系统分为后台管理和前台展示两个视图，通过顶栏切换按钮一键跳转。前台模块拥有独立的后端接口（窗口管理），与大屏模块（纯配置）解耦：

- **后台视图：** 用户管理、设备管理、大屏配置（列表+绑定）
- **前台视图：** 信号源面板 + 拼接大屏画布 + 窗口交互

### 1.2 前台核心功能

```text
前台视图
    |
    +-- 左侧：信号源面板（通道卡片，可拖拽创建窗口）
    |         |
    |         +-- 拖拽信号源到画布 → 直接开窗 → 调后台 API → 后台双写
    |
    +-- 右侧：拼接大屏画布
              |
              +-- 窗口渲染（信号源画面）
              +-- 窗口交互（移动、缩放、关闭）
              +-- 所有操作调后台 API（后台负责存库+转发模拟设备）
```

## 3. 数据库设计

### 3.1 窗口表（SCREEN_WINDOW）

窗口数据由前台模块后端管理，存入管理系统数据库，同时同步到模拟设备。

```sql
CREATE TABLE IF NOT EXISTS SCREEN_WINDOW (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    window_id       VARCHAR(100)  NOT NULL,
    screen_id       BIGINT        NOT NULL,
    device_id       BIGINT        NOT NULL,
    channel_name    VARCHAR(100)  NOT NULL,
    x               INT           NOT NULL DEFAULT 0,
    y               INT           NOT NULL DEFAULT 0,
    width           INT           NOT NULL DEFAULT 1920,
    height          INT           NOT NULL DEFAULT 1080,
    source_type     VARCHAR(50)   DEFAULT '',
    source_url      VARCHAR(500)  DEFAULT '',
    sync_status     VARCHAR(20)   NOT NULL DEFAULT 'synced',
    degraded        INT           NOT NULL DEFAULT 0,
    create_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP,
    update_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_window_screen FOREIGN KEY (screen_id) REFERENCES SCREEN(id) ON DELETE CASCADE
);
```

### 3.2 表关系图

```text
SCREEN (大屏)
  id ──────────────────────────────┐
  screen_name                      │
  rows_count                       │
  cols_count                       │
  cell_width                       │
  cell_height                      │
                                   │
SCREEN_CELL (屏幕单元)              │
  id                               │
  screen_id ───────────────────────┤ 外键 CASCADE
  row_index                        │
  col_index                        │
  device_id ──→ DEVICE.id (可为NULL)
  channel_name                     │
                                   │
SCREEN_WINDOW (窗口，由前台模块管理)   │
  id                               │
  window_id                        │
  screen_id ───────────────────────┤ 外键 CASCADE
  device_id ──→ DEVICE.id          │
  channel_name                     │
  x, y, width, height              │
  source_type, source_url          │
  sync_status ← `synced` | `pending` | `failed`
```

### 3.3 字段说明

| 字段 | 类型 | 必填 | 说明                         |
|------|------|:--:|----------------------------|
| id | BIGINT | 是 | 主键，自增                      |
| window_id | VARCHAR(100) | 是 | 窗口唯一标识                     |
| screen_id | BIGINT | 是 | 所属大屏，外键关联 SCREEN           |
| device_id | BIGINT | 是 | 所属设备                       |
| channel_name | VARCHAR(100) | 是 | 输入通道名称，创建窗口时指定信号源 |
| x, y | INT | 是 | 窗口坐标（1920x1080 基准）         |
| width, height | INT | 是 | 窗口尺寸                       |
| source_type | VARCHAR(50) | 否 | 信号源类型，由设备根据通道配置返回 |
| source_url | VARCHAR(500) | 否 | 信号源地址，由设备根据通道配置返回 |
| sync_status | VARCHAR(20) | 是 | 同步状态：synced/pending/failed |

### 3.4 依赖的其他表

前台模块依赖以下表（由大屏模块创建）：

| 表 | 用途 | 前台读取场景 |
|------|------|------|
| SCREEN | 大屏列表 | 前台大屏下拉选择框 |
| SCREEN_CELL | 单元绑定关系 | 渲染画布网格、确定设备与单元的绑定关系 |
| DEVICE | 设备信息（baseUrl/名称/在线状态/通道名称/窗口数/能力） | 信号源面板（通道展示、能力校验） |

> SCREEN、SCREEN_CELL 建表语句见《大屏模块设计文档》。

## 4. 数据模型

### 4.1 信号源对象（通道）

> 信号源面板展示的是**输入设备**（`deviceCategory = "INPUT"`）的输入通道。设备是单一类型的，输入设备仅提供信号源，输出设备仅用于大屏绑定显示。拖拽通道卡片到画布即可创建窗口，窗口信号源类型和地址由设备返回。

| 字段 | 类型 | 说明 |
|------|------|------|
| deviceId | Number | 设备 ID |
| deviceName | String | 设备名称 |
| channelName | String | 输入通道名称，如 `"HDMI-1"`，不同设备通道名不同 |
| windowCount | Number | 当前通道已创建窗口数 |
| online | Boolean | 设备是否在线，离线后通道卡片禁用 |

### 4.2 窗口对象

| 字段 | 类型 | 说明                        |
|------|------|---------------------------|
| windowId | String | 唯一窗口 ID，前端生成（win-时间戳-随机串） |
| screenId | Number | 所属大屏 ID                   |
| deviceId | Number | 所属设备 ID                   |
| deviceName | String | 设备名称                      |
| channelName | String | 输入通道名称，信号源来自该输入通道     |
| x | Number | 窗口 X 坐标（实际坐标）             |
| y | Number | 窗口 Y 坐标                   |
| width | Number | 窗口宽度                      |
| height | Number | 窗口高度                      |
| sourceType | String | 信号类型，由设备返回                |
| sourceUrl | String | 信号源地址，由设备返回               |
| syncStatus | String | 同步状态（synced/pending）      |
| degraded | Integer | 降级标记（0=正常，1=降级），窗口覆盖的任一输出设备离线时设为 1，由后端同步时自动标记 |
| domEl | DOM Element | 关联的画布 DOM 元素（前端维护）        |

### 4.3 窗口列表管理

| 操作 | 说明 |
|------|------|
| add(window) | 添加窗口到列表 |
| remove(windowId) | 按 windowId 移除 |
| get(windowId) | 按 windowId 查找 |
| clear() | 清空所有窗口 |

### 4.4 前后台切换状态

| 字段 | 取值 | 说明 |
|------|------|------|
| current | `'backend'` | 当前在后台管理视图 |
| | `'frontend'` | 当前在前台展示视图 |

切换时：显示/隐藏侧边栏、后台面板、前台视图，进入前台时自动加载大屏详情。

## 5. 接口

### 5.1 接口汇总

前台模块后端提供以下窗口管理接口（大屏配置接口见《大屏模块设计文档》）：

| 方法 | 路径 | 用途 | 场景 |
|------|------|------|------|
| POST | `/screen/{id}/window` | 创建窗口 | 拖拽开窗 |
| PUT | `/screen/{id}/window/{wid}` | 更新窗口位置/大小 | 拖拽/缩放释放后 |

| DELETE | `/screen/{id}/windows` | 一键清空窗口 | 清空所有窗口 |

> 大屏配置接口（GET /screen/page、GET /screen/{id} 等）见《大屏模块设计文档》。

### 5.2 接口详情


> 大屏配置接口详情（5.2.1~5.2.6）见《大屏模块设计文档》。

## 6. 要完成的功能（流程图）

### 6.1 前后台切换

```text
登录 → 后台视图（默认）
  │
  ├── 点击 [前台展示] → 隐藏侧边栏 + 后台视图
  │     ├── 加载大屏列表 → 选择大屏 → 渲染画布 + 信号源 + 窗口
  │     └── 无大屏 → 提示先创建
  │
  └── 点击 [后台管理] / [返回后台] → 显示侧边栏 + 后台视图
```

### 6.2 拖拽信号源开窗

```text
拖拽信号源卡片 → 释放到画布 → 定位所在单元 → 找到对应设备 → 直接创建窗口
  │
  └── 生成 windowId → 调 ScreenApi.createWindow()
       └── 后台双写 → 返回成功 → 画布渲染窗口
```

## 7. 机制和要注意的点

### 7.1 前后台切换机制

- 使用 `AppMode.current` 全局变量标记当前模式
- 切换时用 `display: none/flex` 控制显隐，不做销毁重建
- **后台 → 前台：** 隐藏侧边栏，全屏显示前台。加载大屏 → 渲染画布 → 加载信号源 → 恢复窗口
- **前台 → 后台：** 显示侧边栏 + 后台面板。**不销毁画布和窗口**，切回前台时直接恢复

### 7.2 信号源面板机制

**信号源来源：** 从输入设备列表获取，按设备 → 输入通道分组展示通道卡片。

**加载流程：**

```text
进入前台 → 选择大屏 → 调后端接口获取信号源列表（后端强制过滤 device_category = "INPUT"，仅返回输入设备）
  → 遍历设备 → 调 GET /device/{id}/capability 获取设备能力（查 DEVICE 表）
  → 按 设备 → 输入通道 分组展示通道卡片（可拖拽）
  → 根据大屏已绑定输出设备的 `maxWindows` 控制通道卡片的拖拽可用性
```

**通道卡片：**

```html
<!-- 设备分组 -->
<div class="source-group">
  <div class="source-group-title">REST-Node-01（输入通道：HDMI-1）</div>
  <!-- 通道卡片（可拖拽到画布创建窗口） -->
  <div class="channel-card" draggable="true"
       data-device-id="1" data-channel-name="HDMI-1">
    <span class="channel-name">HDMI-1</span>
    <span class="channel-window-count">已创建 2 窗口</span>
  </div>
</div>
```

**通道与窗口约束：**

- 后端信号源接口强制过滤 `deviceCategory = "INPUT"`，输出设备**不会**出现在信号源面板中
- 输入通道**不限制**窗口数量，通道卡片始终可拖拽
- 大屏窗口总数受输出设备 `maxWindows` 限制：大屏窗口总数 <= 所有已绑定输出设备 `maxWindows` 中最小的值，超限时所有通道卡片禁用拖拽
- 拖拽通道卡片到画布释放时，自动创建窗口，`sourceType` 和 `sourceUrl` 由设备根据通道配置返回
- 设备能力由 `GET /device/{id}/capability` 获取（查 DEVICE 表），`supportMove`/`supportResize`/`supportOverlay` 控制窗口交互

**离线处理：** 设备离线后，该设备下所有通道卡片变灰 + 不可拖拽。设备恢复上线后，通道卡片恢复可用。

### 7.3 拖拽开窗机制

**三阶段：**

| 阶段 | 触发 | 操作                                                                                                                                  |
|------|------|-------------------------------------------------------------------------------------------------------------------------------------|
| mousedown | 用户按住通道卡片 | 创建拖拽预览，携带 deviceId 和 channelName                                                                                                        |
| mousemove | 鼠标移动 | 预览跟随鼠标，检测是否在画布内                                                                                                                     |
| mouseup | 释放到画布上 | 校验：大屏窗口总数 <= 所有已绑定输出设备 maxWindows 中最小的值 → 计算坐标 + 确定覆盖的单元列表，校验覆盖单元均已绑定设备（未绑定的单元拒绝，已绑定但设备离线的允许降级创建） → 调后台 API 创建窗口（sourceType 和 sourceUrl 由设备返回） |

**单元定位与设备映射：**

```javascript
// 根据释放位置确定落在哪个单元
function getCellAtPos(x, y, cols, rows, canvasW, canvasH) {
    var cellW = canvasW / cols;
    var cellH = canvasH / rows;
    return {
        row: Math.floor(y / cellH),
        col: Math.floor(x / cellW)
    };
}

// 根据单元位置找到绑定的设备
function getDeviceForCell(row, col, cells) {
    var cell = cells.find(c => c.rowIndex === row && c.colIndex === col);
    return cell ? cell.device : null;
}
```

> 窗口可跨单元放置，覆盖的所有单元必须已绑定设备（`device_id` 非 NULL）。已绑定但设备**离线**的单元允许窗口覆盖，窗口创建后进入降级状态（见 7.10）。未绑定设备的单元上不能有窗口覆盖。

**放置位置计算：**

```javascript
function calcDropPosition(e, canvasEl, cellSize, cols, rows) {
    var canvasRect = canvasEl.getBoundingClientRect();
    var pixelX = e.clientX - canvasRect.left;
    var pixelY = e.clientY - canvasRect.top;
    // 画布总分辨率 = 单设备分辨率 × 行列数
    var canvasW = 1920 * cols;
    var canvasH = 1080 * rows;
    var actualX = Math.round(pixelX * canvasW / (cellSize * cols));
    var actualY = Math.round(pixelY * canvasH / (cellSize * rows));
    actualX = Math.max(0, Math.min(actualX, canvasW - canvasW/2));
    actualY = Math.max(0, Math.min(actualY, canvasH - canvasH/2));
    return { x: actualX, y: actualY };
}
```

### 7.4 窗口状态管理

**窗口状态管理方式：**

| 层级 | 存储 | 作用 |
|------|------|------|
| 后台 SCREEN_WINDOW 表 | 持久化 | 权威数据源，集中管理 |
| 模拟设备 DEVICE_WINDOW 表 | 持久化 | 执行层，设备重启不丢 |
| 前台 ScreenWindows.list | 内存 | 画布渲染缓存 |

**窗口操作流程：**

```
创建/更新：前台交互 → 调后台 API → 后台：①存 SCREEN_WINDOW + ②通过 DeviceDriver 统一接口转发设备
删除：    前台交互 → 调后台 API → 后台：①通过 DeviceDriver 统一接口转发设备关闭 → ②删 SCREEN_WINDOW

**状态恢复：** 进入前台时从大屏详情的 `windows` 字段加载，无需额外请求。


**双写机制：**

管理系统在每个窗口操作中做两件事：

**创建/更新：先写数据库，再同步设备**

| 步骤 | 操作 | 失败处理 |
|------|------|------|
| ① 写数据库 | INSERT/UPDATE SCREEN_WINDOW | 事务回滚，返回错误 |
| ② 转发设备 | 计算窗口覆盖的单元列表 → 拆分坐标 → 逐个通过 DeviceDriver 统一接口调设备 | 更新 syncStatus，不阻塞返回 |

**删除：先同步设备，再删数据库**

| 步骤 | 操作 | 失败处理 |
|------|------|------|
| ① 转发设备 | 计算窗口覆盖的单元列表 → 逐个通过 DeviceDriver 统一接口调设备关闭窗口 | 返回错误，不删数据库 |
| ② 删数据库 | DELETE SCREEN_WINDOW | 事务回滚 |

**关键原则：**
- 创建/更新：数据库写成功即操作完成，设备同步失败不影响主流程
- 删除：设备同步成功才删数据库，失败保留记录供重试
```
### 7.5 同步状态标记

前台画布窗口标题栏显示同步状态：

| syncStatus | 前台标记 | 含义 |
|------|------|------|
| `synced` | 无标记（或绿色小圆点） | 正常 |
| `pending` | 黄色标记"待同步" | 数据库有记录，模拟设备未同步 |
| `failed` | 红色标记"同步失败" | 同步失败 |

**设备恢复自动同步（异步）：**

GET /windows 只读数据库，不触发同步操作。同步由后台定时任务独立完成：

```java
// 定时任务：每 30 秒扫描一次，重试 pending/failed 窗口
@Scheduled(fixedDelay = 30_000)
public void retryPendingWindows() {
    List<ScreenWindow> pending = screenWindowMapper.selectBySyncStatus("pending", "failed");
    for (ScreenWindow w : pending) {
        try {
            trySyncToDevice(w);  // 重试推送给模拟设备
        } catch (Exception e) {
            log.warn("窗口 {} 同步失败，等待下次重试: {}", w.getWindowId(), e.getMessage());
        }
    }
}
```
### 7.6 画布自适应渲染

**单元尺寸计算：**

```javascript
function calcCellSize(rows, cols, containerW, containerH) {
    var gap = 4;  // 单元间距
    var w = Math.floor((containerW - gap * (cols + 1)) / cols);
    var h = Math.floor((containerH - gap * (rows + 1)) / rows);
    return Math.max(Math.min(w, h), 200);  // 最小 200px
}
```

**画布居中：** `display: flex; align-items: center; justify-content: center;`

**坐标换算：** 画布总分辨率 = 单设备分辨率 × 行列数：

```javascript
var canvasW = 1920 * cols;  // 拼接大屏总宽度
var canvasH = 1080 * rows;  // 拼接大屏总高度

// 实际坐标 → 画布像素坐标
function toPixel(actualCoord, canvasSize, cellSize) {
    return actualCoord * cellSize / canvasSize;
}
// 画布像素坐标 → 实际坐标
function toActual(pixel, canvasSize, cellSize) {
    return Math.round(pixel * canvasSize / cellSize);
}
```

### 7.7 窗口交互约束

**拖拽约束：**
- `left >= 0`，`top >= 0`
- `left + width <= 画布宽度`，`top + height <= 画布高度`
- 受设备能力 `supportMove` 控制：`supportMove=0` 时窗口不可拖拽

**缩放约束：**
- 最小尺寸：`width >= 100px`，`height >= 60px`（画布像素）
- 8 个方向缩放把手
- 受设备能力 `supportResize` 控制：`supportResize=0` 时窗口不可缩放

| 把手 | 调整逻辑 |
|------|------|
| e(右) | 只调整 width |
| s(下) | 只调整 height |
| se(右下) | 同时调整 width 和 height |
| w(左) | 调整 left 和 width |
| n(上) | 调整 top 和 height |
| nw(左上) | 同时调整 left, top, width, height |
| ne(右上) | 调整 top, width, height |
| sw(左下) | 调整 left, width, height |

**设备能力约束：**

| 约束项 | 规则                                                                                                           | 来源 |
|------|--------------------------------------------------------------------------------------------------------------|------|
| 窗口数量 | 输入通道无限制；大屏窗口总数 <= 所有已绑定输出设备 `maxWindows` 中最小的值（大屏级别），超限时所有通道卡片禁用拖拽 | DEVICE 表 max_windows |
| 窗口移动 | 受 `supportMove` 控制，0 时禁用拖拽                                                                                   | DEVICE 表 support_move |
| 窗口缩放 | 受 `supportResize` 控制，0 时禁用缩放                                                                                 | DEVICE 表 support_resize |
| 窗口重叠 | 受 `supportOverlay` 控制，0 时阻止重叠                                                                                | DEVICE 表 support_overlay |




### 7.8 窗口位置/大小保存机制

窗口的位置、大小、归属大屏等信息在以下时机持久化到数据库：

**创建窗口时保存：**

```text
拖拽输入通道卡片 → 释放到画布 → 计算坐标 (x,y) + 定位所在单元
  → 调 POST /screen/{id}/window 创建窗口
    ├── 写入：windowId, screenId, deviceId, channelName, x, y, width, height, sourceType, sourceUrl
    └── 双写（先写 DB，再通过 DeviceDriver 转发设备）
```

**拖拽移动后保存：**

```text
mousedown 标题栏 → mousemove 更新 CSS → mouseup
  → 计算新坐标 (x, y)
  → 调 PUT /screen/{id}/window/{wid} 更新位置
    └── 双写（先写 DB，再通过 DeviceDriver 转发设备）
```

**缩放后保存：**

```text
mousedown 把手 → mousemove 调整尺寸 → mouseup
  → 计算新尺寸 (width, height)
  → 调 PUT /screen/{id}/window/{wid} 更新尺寸
    └── 双写（先写 DB，再通过 DeviceDriver 转发设备）
```

**关闭窗口时删除：**

```text
点击 [X] → 确认
  → 调 DELETE /screen/{id}/window/{wid}
    ├── ① 先通过 DeviceDriver 转发设备关闭窗口（失败则返回错误，不删 DB）
    └── ② 删除 DB 记录
```

> **降级窗口例外：** 窗口处于降级状态时（覆盖的某输出设备离线），关闭逻辑见 7.10.4。

**一键清空大屏窗口：**

```text
点击 [一键清空] → 确认
  → 调 DELETE /screen/{id}/windows
    ├── 遍历所有窗口，逐个：① 通过 DeviceDriver 转发设备关闭 → ② 删除 DB 记录
    └── 前台清空画布 + 窗口列表
```

> 一键清空时，每个窗口独立执行删除流程（先同步设备，再删数据库）。某个窗口同步失败不影响其他窗口继续清空，失败的窗口保留记录等待重试。
### 7.9 跨单元窗口拆分机制

窗口在画布上的 x/y/width/height 是**大屏全局坐标**，SCREEN_WINDOW 只存一条记录。同步到设备时，后端按窗口覆盖的单元动态拆分为子窗口：

```text
大屏: 2×2, 每单元 1920×1080
窗口: x=500, y=0, w=1920, h=1080

覆盖单元: (0,0) 和 (0,1)
  ├── 设备A (单元 0,0): 子窗口 x=500, y=0, w=1420, h=1080
  └── 设备B (单元 0,1): 子窗口 x=0, y=0, w=500, h=1080
```

**拆分逻辑：**

```java
// 窗口覆盖的单元范围
int startRow = window.y / cellHeight;
int endRow = (window.y + window.height - 1) / cellHeight;
int startCol = window.x / cellWidth;
int endCol = (window.x + window.width - 1) / cellWidth;

for (int r = startRow; r <= endRow; r++) {
    for (int c = startCol; c <= endCol; c++) {
        ScreenCell cell = findCell(screenId, r, c);
        if (cell == null || cell.getDeviceId() == null) continue;  // 跳过未绑定

        // 计算该单元内的子窗口坐标
        int subX = Math.max(0, window.x - c * cellWidth);
        int subY = Math.max(0, window.y - r * cellHeight);
        int subW = Math.min(cellWidth - subX, window.x + window.width - c * cellWidth - subX);
        int subH = Math.min(cellHeight - subY, window.y + window.height - r * cellHeight - subY);

        // 推送给设备
        syncToDevice(cell.getDeviceId(), cell.getChannelName(), subX, subY, subW, subH, ...);
    }
}
```

**拖拽/缩放时：** 只更新 SCREEN_WINDOW 的一条记录，窗口覆盖的单元可能变化，同步时重新计算拆分。

**关闭时：** 遍历所有覆盖单元，逐个通知设备关闭子窗口。

### 7.10 跨单元离线降级处理

**场景：** 大屏多单元，窗口横跨多个输出设备，其中某个输出设备离线。

**策略：降级标记 + 自动补推。**

#### 7.10.1 同步时降级

创建/移动/缩放窗口时，遍历窗口覆盖的所有单元绑定的输出设备：

1. 设备**在线** → 正常推送子窗口
2. 设备**离线** → 跳过推送，不报错，窗口标记 `degraded = true`
3. 所有覆盖设备均在线 → `degraded = false`

```text
窗口覆盖设备 A（在线）、B（离线）
  → 推送 A 的子窗口，跳过 B
  → 窗口 degraded = true
```

#### 7.10.2 前端显示

`degraded = true` 的窗口画布上显示红色虚线边框，hover 时 tooltip 提示"部分设备离线，画面不完整"。

#### 7.10.3 设备恢复上线后自动补推

1. 心跳检测到设备恢复在线
2. 遍历该设备绑定的所有单元，找出覆盖这些单元的 `degraded = true` 窗口
3. 对每个降级窗口重新计算拆分，补推该设备对应的子窗口
4. 补推成功后，重新检查窗口：若所有覆盖设备均在线，则 `degraded = false`，清除降级标记

**实现方式：** 复用 7.5 的定时任务 `retryPendingWindows()`。降级窗口在创建时 `syncStatus = "pending"`，设备离线导致推送失败，定时任务扫描到 `pending` 状态后重试推送。设备恢复后，定时任务在下一次扫描时自动补推成功，更新 `syncStatus = "synced"` 同时 `degraded = false`。

```text
设备 B 离线 → 窗口创建 → syncStatus=pending, degraded=true
设备 B 心跳恢复 → 定时任务扫描 → 重试推送 B 的子窗口
  → 推送成功 → syncStatus=synced, degraded=false
```

#### 7.10.4 关闭窗口时

关闭窗口不受降级影响，直接遍历所有覆盖单元，通知在线设备关闭子窗口，**同时清除 degraded 标记**。

﻿﻿# 设备管理模块设计文档

## 1. 概述

设备管理模块是异构硬件设备管控系统的核心模块之一，负责管理系统中所有硬件设备的注册、查询、状态监控等功能。该模块通过数据库持久化存储设备信息，支持手动添加设备，并通过 `DeviceDriver` 统一接口获取设备实时信息与运行状态。

### 1.1 统一返回格式

沿用项目 `Result<T>` 封装（位于 `demo1-common` 模块）：

```json
{
  "code": 1,     // 1=成功，0=失败
  "msg": null,   // 失败时包含错误信息
  "data": {}     // 业务数据
}
```

## 3. 数据库设计

### 3.1 建表 SQL

文件位置：`demo1-server/src/main/resources/schema.sql`，在现有 USER 表建表语句之后追加。

```sql
CREATE TABLE IF NOT EXISTS DEVICE (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id       VARCHAR(100)  NOT NULL UNIQUE,   -- 设备唯一标识
    device_name     VARCHAR(200)  NOT NULL,           -- 设备名称
    device_type     VARCHAR(50)   DEFAULT 'REST',     -- 设备类型
    model           VARCHAR(100)  DEFAULT '',         -- 设备型号
    serial_number   VARCHAR(100)  DEFAULT '',         -- 序列号
    output_channels INT           DEFAULT 1,          -- 输出通道数
    max_resolution  VARCHAR(50)   DEFAULT '1920x1080',-- 最大分辨率
    base_url        VARCHAR(300)  NOT NULL,           -- 设备 REST API 基地址
    enabled         INT           DEFAULT 1,           -- 是否启用（1=启用，0=禁用）
    online          INT           DEFAULT 0,           -- 在线状态（1=在线，0=离线）
    last_heartbeat  TIMESTAMP     NULL,                -- 最后心跳时间
    create_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP,
    update_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);
```

> `application.yaml` 中已配置 `spring.sql.init.mode: always`，启动时自动执行。`CREATE TABLE IF NOT EXISTS` 不会覆盖已有数据，与 USER 表无冲突。

### 3.2 字段说明

| 字段 | 类型 | 必填 | 不可重复 | 说明 |
|------|------|:--:|:----:|------|
| id | BIGINT | 是 |  是   | 主键，自增 |
| device_id | VARCHAR(100) | 是 |  是   | 设备唯一标识，如 `device-001` |
| device_name | VARCHAR(200) | 是 |  是   | 设备名称，如 `REST-Node-01` |
| device_type | VARCHAR(50) | 否 |  否   | 设备类型，默认 `REST` |
| model | VARCHAR(100) | 否 |  否   | 设备型号，如 `DS-D2055NH-A` |
| serial_number | VARCHAR(100) | 否 |  是   | 序列号 |
| output_channels | INT | 否 |  否   | 输出通道数，默认 1 |
| max_resolution | VARCHAR(50) | 否 |  否   | 最大分辨率，默认 `1920x1080` |
| base_url | VARCHAR(300) | 是 |  否   | 设备 REST API 基地址，如 `http://localhost:8086` |
| enabled | INT | 否 | — | 是否启用，默认 `1`。`1`=启用，`0`=禁用，禁用后可删除 |
| online | INT | 否 | — | 在线状态，默认 `0`。`1`=在线，`0`=离线，由定时心跳更新 |
| last_heartbeat | TIMESTAMP | 否 | — | 最后心跳时间，用于判断离线时长 |
| create_time | TIMESTAMP | 否 | — | 创建时间 |
| update_time | TIMESTAMP | 否 | — | 最后更新时间 |

## 4. 数据模型

### 4.1 实体类 — SimDeviceInfo

位于 `demo1-common` 模块，存放纯设备描述信息，**不包含连接地址**（连接地址由 `DeviceEndpoint` 管理）：

```java
@Data
public class SimDeviceInfo {
    private String deviceId;       // 设备唯一标识
    private String deviceName;     // 设备名称
    private String deviceType;     // 设备类型
    private String model;          // 设备型号
    private String serialNumber;   // 序列号
    private int outputChannels;    // 输出通道数
    private String maxResolution;  // 最大分辨率
}
```

> **为什么没有 `baseUrl`？**  `baseUrl` 是管控系统才需要的连接信息，模拟设备不需要。应放在 `DeviceEndpoint` 中，由管控系统单独管理。

### 4.2 DeviceEndpoint — 设备连接信息

位于 `demo1-server` 的 `driver/` 包下，管控系统独有：

```java
@Data
public class DeviceEndpoint {
    private String deviceId;       // 设备唯一标识
    private String deviceType;     // 设备类型：REST / TLV
    private String baseUrl;        // REST 设备基地址
    private String ip;             // TLV 设备 IP（预留）
    private int port;              // TLV 设备端口（预留）
}
```

### 4.3 DevicePageDTO — 分页查询入参

放在 `demo1-server` 的 `common/` 包下：

```java
@Data
public class DevicePageDTO {
    private String deviceName;    // 设备名称（模糊搜索）
    private String deviceType;    // 设备类型（精确匹配）
    private Integer page;         // 页码
    private Integer pageSize;     // 每页数量
}
```

### 4.4 DevicePageVO — 分页返回 VO

放在 `demo1-server` 的 `common/` 包下。继承 `SimDeviceInfo` 并新增 `baseUrl` 和 `online`，解决分页响应需要返回 `baseUrl` 和 `online` 但 `SimDeviceInfo` 不含这两个字段的问题：

```java
@Data
@EqualsAndHashCode(callSuper = true)
public class DevicePageVO extends SimDeviceInfo {
    private String baseUrl;        // 设备 REST API 基地址
    private Integer online;        // 在线状态（1=在线，0=离线）
}
```

### 4.5 AddDeviceRequest — 添加设备请求 DTO

放在 `demo1-server` 的 `common/` 包下。仅含两个定位字段，其余信息由管控系统连接模拟设备后自动补全：

```java
@Data
public class AddDeviceRequest {
    private String deviceId;
    private String baseUrl;
}
```

### 4.6 设备状态 — SimDeviceStatus

位于 `demo1-common` 模块：

```java
@Data
public class SimDeviceStatus {
    private String deviceId;       // 设备唯一标识
    private boolean online;        // 是否在线
    private int windowCount;       // 当前窗口数量
    private String uptime;         // 设备启动时间
}
```

### 5.2 手动添加设备

```
POST /device
```

**请求体：**

```json
{
  "deviceId": "device-001",
  "baseUrl": "http://localhost:8086"
}
```

**必填字段：** deviceId、baseUrl

**数据流向：**

1. Controller 接收请求体 → 映射为 `AddDeviceRequest`（仅 deviceId + baseUrl）
2. Controller 调用 `deviceService.addDevice(deviceId, baseUrl)`
3. Service 先校验 deviceId 是否已存在
4. Service 通过 `RestDeviceDriver.getInfo(DeviceEndpoint)` 请求模拟设备，拉取设备真实信息（deviceName、deviceType、model、outputChannels、maxResolution 等）
5. Service 在事务中执行：`deviceMapper.insert(deviceInfo)` + `deviceMapper.insertBaseUrl(deviceId, baseUrl)`

**核心设计：** 用户只需提供"定位信息"（baseUrl + deviceId），管控系统连接模拟设备后自动补全设备描述字段，保证数据库与模拟设备保持一致。

**成功响应：**

```json
{
  "code": 1,
  "msg": null,
  "data": {
    "deviceId": "device-001",
    "deviceName": "REST-Node-01",
    "deviceType": "REST",
    "model": "DS-D2055NH-A",
    "outputChannels": 2,
    "maxResolution": "1920x1080"
  }
}
```

**失败响应（参数校验失败）：**

```json
{
  "code": 0,
  "msg": "设备ID不能为空",
  "data": null
}
```

**失败响应（设备ID重复）：**

```json
{
  "code": 0,
  "msg": "设备ID已存在: device-001",
  "data": null
}
```

**失败响应（模拟设备上不存在该设备）：**

```json
{
  "code": 0,
  "msg": "模拟设备上未找到设备: device-999",
  "data": null
}
```

**失败响应（模拟设备连接失败）：**

```json
{
  "code": 0,
  "msg": "无法连接模拟设备: http://localhost:8086，请检查设备是否在线",
  "data": null
}
```

### 5.3 删除设备

```
DELETE /device/{deviceId}
```

**请求示例：**

```
DELETE http://localhost:8085/device/device-003
```

**数据流向：**

1. Controller 调用 `deviceService.deleteDevice(deviceId)`
2. Service 查询设备是否存在，不存在则抛异常
3. Service 校验 `enabled` 字段：若为 `1`（启用），拒绝删除
4. 若为 `0`（禁用），执行 `deviceMapper.deleteByDeviceId(deviceId)` 删除

**成功响应：**

```json
{
  "code": 1,
  "msg": null,
  "data": null
}
```

**失败响应（设备不存在）：**

```json
{
  "code": 0,
  "msg": "设备不存在: device-003",
  "data": null
}
```

**失败响应（设备已启用，不可删除）：**

```json
{
  "code": 0,
  "msg": "设备已启用，请先禁用后再删除",
  "data": null
}
```

### 5.7 搜索发现设备

管控系统通过 UDP 广播主动搜索局域网内的模拟设备，模拟设备收到广播后回复自身信息。

```
POST /device/discover
```

**请求体：** 无（或空 JSON `{}`）

**数据流向：**

1. Controller 调用 `deviceService.discover()`
2. Service 通过 UDP 向 `255.255.255.255:9999` 发送广播 `{"action":"discovery"}`
3. 等待 3 秒，收集所有模拟设备的回复
4. 解析回复，返回发现的设备列表

**成功响应：**

```json
{
  "code": 1,
  "msg": "发现 2 个模拟设备进程",
  "data": [
    {
      "baseUrl": "http://192.168.1.100:8086",
      "devices": [
        {
          "deviceId": "device-001",
          "deviceName": "REST-Node-01",
          "deviceType": "REST",
          "model": "DS-D2055NH-A",
          "outputChannels": 2,
          "maxResolution": "1920x1080",
          "added": false
        },
        {
          "deviceId": "device-002",
          "deviceName": "REST-Node-02",
          "deviceType": "REST",
          "model": "DS-D2055NH-B",
          "outputChannels": 2,
          "maxResolution": "1920x1080",
          "added": true
        }
      ]
    }
  ]
}
```

**未发现设备：**

```json
{
  "code": 1,
  "msg": "未发现设备",
  "data": []
}
```

**防重复设计：**

| 方式 | 防重复机制 |
|------|-----------|
| 手动添加 | 数据库 `device_id` UNIQUE 约束，重复时返回 `"设备ID已存在: xxx"` |
| 搜索发现 | `DeviceDiscoveryService` 查询数据库已添加的设备 ID，搜索结果中标记 `"added": true`；前端对已添加的设备显示"已添加"并禁用按钮，防止重复提交 |

- `baseUrl`：模拟设备进程地址，前端可直接用于"添加设备"表单
- `devices`：该进程内暴露的所有设备列表
- 前端展示搜索结果后，用户点击"添加"，自动填入 `deviceId` 和 `baseUrl`，走 5.2 手动添加流程

**请求示例：**

```
PUT http://localhost:8085/device/device-001/enabled
```

**成功响应：**

```json
{
  "code": 1,
  "msg": "设备已启用",
  "data": null
}
```

**失败响应（设备不存在）：**

```json
{
  "code": 0,
  "msg": "设备不存在: device-001",
  "data": null
}
```

**失败响应（重复操作）：**

```json
{
  "code": 0,
  "msg": "设备已是禁用状态",
  "data": null
}
```

**规则：**

| 规则 | 说明 |
|------|------|
| 启用不能删除 | 删除前需先禁用，否则返回 `"设备已启用，请先禁用后再删除"` |
| 禁用不可重复 | 已禁用设备再次禁用返回 `"设备已是禁用状态"` |
| 启用不可重复 | 已启用设备再次启用返回 `"设备已是启用状态"` |
| 新增设备默认为启用 | 添加设备时 `enabled` 默认 `1` |

> **注意：** 启用/禁用仅修改数据库 `enabled` 字段（1=启用，0=禁用），控制删除权限，**不会断开或关闭设备连接**。设备查询、状态获取、窗口操作等接口不受 `enabled` 状态影响。

### 5.10 心跳检测机制

管控系统启动后，通过 `@Scheduled` 定时任务定期向所有设备发送心跳请求，更新数据库中的在线状态。

**实现方式：**

- 使用 Spring `@Scheduled` 注解，默认每 30 秒执行一次
- `@Scheduled(fixedRate = 30000)`，`fixedRate` 保证两次任务开始时间间隔固定
- 由于是纯 CPU 操作（HTTP 调用），不涉及共享资源竞争，无需加锁

**数据流向：**

1. 定时任务触发 → 调用 `deviceService.updateOnlineStatus()`
2. Service 查询所有设备，逐个调用 `DeviceDriver.getStatus(endpoint)`
3. 请求成功 → `updateOnline(deviceId, 1, now)` 写入在线 + 心跳时间
4. 请求超时/连接失败 → `updateOnline(deviceId, 0, now)` 写入离线 + 心跳时间

**数据库更新：**

| 字段 | 在线时 | 离线时 |
|------|--------|--------|
| online | `1` | `0` |
| last_heartbeat | 当前时间 | 当前时间 |

**前端展示：**

- 分页列表返回 `online` 字段，前端根据 `1`/`0` 显示绿色/灰色状态图标
- 列表可展示 `last_heartbeat` 时间，让用户知道设备最后在线时间

**定时任务配置：**

```java
@Scheduled(fixedRate = 30000)  // 30 秒一次
public void heartbeat() {
    deviceService.updateOnlineStatus();
}
```

## 6. 设备接入说明

管控系统通过 `DeviceDriver` 统一接口调用设备，`baseUrl` 由 `DeviceEndpoint` 携带，不混入 `SimDeviceInfo`。

调用链路：

```
前端请求 /device/device-001/info
    │
    v
DeviceController
    │
    v
DeviceServiceImpl.getDeviceInfo("device-001")
    │
    +-- 1. 查数据库 → 拿到 SimDeviceInfo（设备描述） + base_url（连接地址）
    +-- 2. 构建 DeviceEndpoint(deviceId, deviceType, baseUrl)
    +-- 3. restDeviceDriver.getInfo(endpoint)
            │
            +-- HTTP GET http://localhost:8086/simulator/device/device-001/info
                    │
                    v
            模拟设备 (demo1-simulator :8086)

关键：SimDeviceInfo 只存设备描述，baseUrl 走 DeviceEndpoint，两清。
```

> 添加设备时，`baseUrl` 填写模拟设备地址，如 `http://localhost:8086`。

## 7. 设备发现机制

### 7.1 概述

管控系统通过 UDP 广播主动搜索局域网内的模拟设备，模拟设备启动后自动监听 UDP 端口，收到搜索请求后回复自身信息。

**技术选型：** 纯 JDK 实现，无需额外依赖。

| 组件 | 技术 | 说明 |
|------|------|------|
| UDP 通信 | `java.net.DatagramSocket` + `DatagramPacket` | JDK 自带 |
| 广播地址 | `255.255.255.255` | 局域网广播 |
| JSON 序列化 | Jackson `ObjectMapper` | Spring Boot 内置 |
| 超时控制 | `socket.setSoTimeout(3000)` | 3 秒超时 |

### 7.2 交互流程

```
管控系统 (demo1-server)              模拟设备 (demo1-simulator)
       │                                      │
       │── UDP 广播:255.255.255.255:9999 ──→  │
       │   {"action":"discovery"}             │
       │                                      │── DiscoveryListener 收到广播
       │                                      │── 构造回复 JSON
       │←── UDP 单播回复 ────────────────────│
       │   {"baseUrl":"http://x.x.x.x:8086",  │
       │    "devices":[{...},{...}]}          │
       │                                      │
       │  等待 3 秒收集所有回复                  │
       │  返回发现的设备列表给前端                │
```

### 7.3 模拟设备端：DiscoveryListener

位于 `demo1-simulator`，在 `@PostConstruct` 中启动守护线程，监听 UDP 9999 端口。

**实现要点：**

- 用 `java.net.DatagramSocket` 监听 9999 端口
- 收到 UDP 报文后解析 JSON，判断 `action` 是否为 `"discovery"`
- 调用 `SimDeviceManager` 获取所有设备信息，构造回复 JSON（含 `baseUrl` + `devices` 列表）
- 通过 `DatagramPacket` 单播回复给请求方
- 异常捕获打日志，不影响主流程

### 7.4 管控系统端：DeviceDiscoveryService

位于 `demo1-server`，负责发送广播和收集回复。

**实现要点：**

- 创建 `DatagramSocket`，开启广播模式，设置 3 秒超时
- 向 `255.255.255.255:9999` 发送 `{"action":"discovery"}` 广播
- 循环接收回复，解析 JSON 为 `DiscoveredNode` 对象
- 超时后停止收集，返回结果列表
- 异常捕获打日志

### 7.5 数据模型

```java
// 模拟设备回复的 JSON 结构
@Data
public class DiscoveredNode {
    private String baseUrl;                   // 如 http://192.168.1.100:8086
    private List<DiscoveredDevice> devices;   // 该进程内所有设备
}

@Data
public class DiscoveredDevice {
    private String deviceId;
    private String deviceName;
    private String deviceType;
    private String model;
    private Integer outputChannels;
    private String maxResolution;
    private boolean added;                    // 是否已添加到管控系统
}
```

## 8. Service 层设计

### 8.1 DeviceService 接口

```java
public interface DeviceService {
    SimDeviceInfo addDevice(String deviceId, String baseUrl);
    void deleteDevice(String deviceId);
    void setEnabled(String deviceId, int enabled);
    SimDeviceInfo refreshDevice(String deviceId);
    void updateOnlineStatus();
    PageResult<DevicePageVO> getPage(DevicePageDTO pageDTO);
    SimDeviceInfo getDeviceInfo(String deviceId);
    SimDeviceStatus getDeviceStatus(String deviceId);
    List<DiscoveredNode> discover();
}
```

### 8.2 DeviceServiceImpl 核心逻辑

| 方法 | 逻辑说明 |
|-----|----------|
| addDevice | 校验 deviceId 是否已存在 → 构建 DeviceEndpoint → 调用 `DeviceDriver.getInfo()` 拉取设备真实信息 → `@Transactional` 保证 `insert(deviceInfo)` + `insertBaseUrl` 原子性 |
| deleteDevice | 根据 deviceId 查询 → 查不到则抛异常 → 校验 `enabled` 状态，已启用则拒绝删除 → 查到了则删除 |
| setEnabled | 查询设备是否存在 → 校验当前 `enabled` 状态，重复操作则拒绝 → `updateEnabled(deviceId, enabled)` |
| refreshDevice | 查数据库拿到 `DeviceEndpoint` → 调用 `DeviceDriver.getInfo()` 拉取最新信息 → 更新数据库（deviceName、model、outputChannels 等）→ 返回更新后的 `SimDeviceInfo` |
| updateOnlineStatus | 查询所有设备 → 遍历每个设备，调用 `DeviceDriver.getStatus()` → 请求成功则 `updateOnline(deviceId, 1, now)`，失败则 `updateOnline(deviceId, 0, now)` |
| getPage | 使用 PageHelper 分页 → `pageQuery` 返回 `Page<DevicePageVO>`（含 baseUrl + online）→ 转为 `PageResult` |
| getDeviceInfo | 查数据库获取 `SimDeviceInfo` + `baseUrl` → 构建 `DeviceEndpoint` → 调用 `DeviceDriver.getInfo()` |
| getDeviceStatus | 查数据库获取 `SimDeviceInfo` + `baseUrl` → 构建 `DeviceEndpoint` → 调用 `DeviceDriver.getStatus()` |
| discover | 委托 `DeviceDiscoveryService.discover()` 进行 UDP 广播搜索，返回发现的设备列表 |

> **事务说明：** `addDevice` 需要加 `@Transactional`，保证 `insert(device)` 和 `insertBaseUrl` 两次写入要么都成功要么都回滚。
>
> **添加设备时自动补全：** `addDevice` 不接收设备描述字段，而是由 `DeviceDriver.getInfo()` 从模拟设备拉取真实信息后写入数据库，确保数据一致性。

## 9. Mapper 层设计

### 9.1 DeviceMapper 接口

| 方法 | 说明 |
|------|------|
| `insert(SimDeviceInfo)` | 插入设备描述字段 |
| `insertBaseUrl(deviceId, baseUrl)` | 单独插入 baseUrl |
| `deleteByDeviceId(deviceId)` | 按 deviceId 删除 |
| `updateEnabled(deviceId, enabled)` | 更新启用/禁用状态（1/0） |
| `updateOnline(deviceId, online, lastHeartbeat)` | 更新在线状态与心跳时间 |
| `updateDeviceInfo(SimDeviceInfo)` | 刷新设备信息时更新数据库 |
| `findByDeviceId(deviceId)` | 按 deviceId 查询，返回 SimDeviceInfo（不含 baseUrl） |
| `getBaseUrl(deviceId)` | 单独查询 baseUrl |
| `findAllDeviceIds()` | 查询所有设备 ID，用于心跳遍历 |
| `pageQuery(DevicePageDTO)` | 分页查询，返回 `Page<DevicePageVO>`（含 baseUrl + online） |

### 9.2 ResultMap 设计

两个 ResultMap 分别服务于不同场景：

| ResultMap | 映射实体 | 包含 base_url？ | 用途 |
|-----------|---------|:---:|------|
| `BaseResultMap` | `SimDeviceInfo` | ❌ | `findByDeviceId` 查询 |
| `PageVOMap` | `DevicePageVO` | ✅ | `pageQuery` 分页查询 |

> `BaseResultMap` 不映射 `base_url`，因为 `SimDeviceInfo` > `PageVOMap` 映射 `base_url` 和 `online`，因为 `DevicePageVO` 继承 `SimDeviceInfo` 并增加了 `baseUrl` 和 `online` 字段。

### 9.3 关键 SQL 设计

- **分页查询**：`SELECT * FROM DEVICE`，动态条件拼接 `deviceName`（模糊搜索）+ `deviceType`（精确匹配），按 `id DESC` 排序
- **baseUrl 查询**：`SELECT base_url FROM DEVICE WHERE device_id = #{deviceId}`，只查单列，与 `SimDeviceInfo` 无关

## 10. Controller 层设计

### 10.1 DeviceController 路由规划

```java
@RestController
@RequestMapping("/device")
public class DeviceController {

    @Autowired
    private DeviceService deviceService;

    @PostMapping                        // 添加设备（接收 AddDeviceRequest，仅含 deviceId + baseUrl，调用 deviceService.addDevice）
    @PostMapping("/discover")           // 搜索发现设备
    @DeleteMapping("/{deviceId}")       // 删除设备
    @PutMapping("/{deviceId}/enabled")  // 启用/禁用设备
    @PutMapping("/{deviceId}/refresh")  // 刷新设备信息
    @GetMapping("/page")                // 分页查询
    @GetMapping("/{deviceId}/info")     // 设备信息
    @GetMapping("/{deviceId}/status")   // 设备状态
}
```

> `addDevice` 接收 `AddDeviceRequest`（仅 `deviceId` + `baseUrl` 两个字段），Controller 直接调用 `deviceService.addDevice(request.getDeviceId(), request.getBaseUrl())`，Service 返回从模拟设备拉取的 `SimDeviceInfo`。

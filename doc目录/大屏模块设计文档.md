# 大屏模块设计文档

## 1. 概述

### 1.1 模块定位

大屏模块是异构硬件设备管控系统的**配置**，负责拼接大屏的创建、设备通道绑定。

**核心职责：**
- 创建拼接大屏（定义行列数，自动生成屏幕单元）
- 将设备输出通道绑定到屏幕单元

> **设备类别说明：** 大屏单元仅可绑定**输出设备**（`deviceCategory = "OUTPUT"`），输入设备不可用于大屏绑定。绑定时会校验设备类别，非输出设备拒绝绑定并提示"该设备为输入设备，不可用于大屏绑定"。

## 3. 数据库设计

### 3.1 建表 SQL

在 `demo1-server/src/main/resources/schema.sql` 中追加：

```sql
-- =============================================
-- 大屏配置模块
-- =============================================
CREATE TABLE IF NOT EXISTS SCREEN (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    screen_name     VARCHAR(200)  NOT NULL,
    rows_count      INT           NOT NULL DEFAULT 1,
    cols_count      INT           NOT NULL DEFAULT 1,
    cell_width       INT           NOT NULL DEFAULT 1920,
    cell_height      INT           NOT NULL DEFAULT 1080,
    create_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP,
    update_time     TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS SCREEN_CELL (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    screen_id       BIGINT        NOT NULL,
    row_index       INT           NOT NULL DEFAULT 0,
    col_index       INT           NOT NULL DEFAULT 0,
    device_id       BIGINT        NULL,
    channel_name    VARCHAR(100)  NOT NULL DEFAULT '',
    CONSTRAINT fk_cell_screen FOREIGN KEY (screen_id) REFERENCES SCREEN(id) ON DELETE CASCADE
);

```

### 3.2 表关系图

```text
SCREEN (大屏)
  id ──────────────────────────────┐
  screen_name                      │
  rows_count                       │
  cols_count                       │
  cell_width                       │
  cell_height                      │
                                   │
SCREEN_CELL (屏幕单元)              │
  id                               │
  screen_id ───────────────────────┤ 外键 CASCADE
  row_index                        │
  col_index                        │
  device_id ──→ DEVICE.id (可为NULL)
  channel_name                     │
                                   │
SCREEN_WINDOW (窗口，由前台模块管理)   │
  id                               │
  window_id                        │
  screen_id ───────────────────────┤ 外键 CASCADE
  device_id ──→ DEVICE.id          │
  channel_name                     │
  x, y, width, height              │
  source_type, source_url          │
  sync_status ← `synced` | `pending` | `failed`
  degraded ← 0=正常 | 1=降级（部分单元设备离线）
```

### 3.3 字段说明

**SCREEN（大屏表）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| id | BIGINT | 是 | 主键，自增 |
| screen_name | VARCHAR(200) | 是 | 大屏名称 |
| rows_count | INT | 是 | 行数，默认 1 |
| cols_count | INT | 是 | 列数，默认 1 |
| cell_width | INT | 是 | 单元宽度（px），默认 1920。绑定设备时校验设备分辨率必须匹配 |
| cell_height | INT | 是 | 单元高度（px），默认 1080。绑定设备时校验设备分辨率必须匹配 |

**SCREEN_CELL（屏幕单元表）**

| 字段 | 类型 | 必填 | 说明           |
|------|------|:--:|--------------|
| id | BIGINT | 是 | 主键，自增        |
| screen_id | BIGINT | 是 | 关联大屏，级联删除    |
| row_index | INT | 是 | 行索引，从 0 开始   |
| col_index | INT | 是 | 列索引，从 0 开始   |
| device_id | BIGINT | 否 | 绑定的设备 ID，NULL=未绑定。大屏所有单元必须绑定输出设备后才可用 |
| channel_name | VARCHAR(100) | 是 | 绑定的输出通道名称，必须是该设备已定义的输出通道名之一。仅**输出设备**可绑定，输入设备无输出通道 |

## 5. 接口

### 5.1 接口汇总

| 方法 | 路径 | 用途 | 说明 |
|------|------|------|------|
| POST | `/screen` | 创建大屏 | 自动生成 rows×cols 个单元 |
| GET | `/screen/page` | 分页查询大屏列表 | 含单元数和窗口数 |
| GET | `/screen/{id}` | 获取大屏详情 | 含单元列表 |
| DELETE | `/screen/{id}` | 删除大屏 | 级联删除单元和窗口 |
| PUT | `/screen/{screenId}/cell/{cellId}` | 绑定/更换设备通道 | 查 DEVICE 表校验设备信息及能力后绑定或更换 |


## 6. 要完成的功能（流程图）

### 6.1 大屏配置流程

```text
POST /screen 创建大屏 (rows×cols)
  ├── 自动生成 SCREEN_CELL 单元
  └── 遍历 cells 列表，对每个单元调用绑定设备方法（内部复用 5.2.5 绑定逻辑）
      ├── 校验：查 DEVICE 表确认设备存在、在线、`device_category = "OUTPUT"`（非输出设备拒绝绑定）
      ├── 校验：统计所有大屏中该设备已绑定总数，确保不超过已定义的输出通道数量（outputChannel1、outputChannel2、outputChannel3）
      ├── 校验：查 DEVICE 表获取设备能力字段（maxWindows / supportMove / supportResize / supportOverlay）
      └── 更新 SCREEN_CELL.device_id + channel_name
  └── 任一单元校验失败 → 事务回滚，大屏创建失败

PUT /screen/{id}/cell/{cellId} 更换绑定设备通道
  └── 允许更换单元绑定的输出设备，但不能解绑（所有单元必须一直保持绑定状态）

DELETE /screen/{id} 删除大屏
  └── CASCADE 删除 SCREEN_CELL 和 SCREEN_WINDOW
```



### 6.2 整体业务闭环

```text
用户登录 → 添加设备 → 创建大屏 → 绑定设备输出通道到所有单元（必须全部绑定）
  → 进入前台 → 选择已创建的大屏 → 拖拽输入通道到画布 → 创建窗口 → 后台双写 → 前台渲染交互
```

## 7. 机制和要注意的点

### 7.1 单元绑定校验规则

| 校验项 | 说明 |
|------|------|
| 名称唯一 | 大屏名称不能重复，创建时校验 SCREEN 表 `screen_name` 是否已存在 |
| 设备存在 | 查 DEVICE 表确认 id 存在 |
| 设备已启用 | `enabled=1` |
| 设备在线 | `online=1`，离线设备不允许绑定 |
| 设备类别 | `device_category = "OUTPUT"`，输入设备不允许绑定，提示"该设备为输入设备，不可用于大屏绑定" |
| 通道总数不超限 | 所有大屏中该设备的绑定总数 ≤ 已定义的输出通道数（查 DEVICE 表 output_channel_1、output_channel_2、output_channel_3，非空即算一个可用通道） |
| 分辨率匹配 | 设备 `maxResolution` 与单元 `cellWidth x cellHeight` 匹配（查 DEVICE 表 max_resolution 字段） |
| 设备能力 | 查 DEVICE 表获取能力字段（maxWindows / supportMove / supportResize / supportOverlay），返回供前台约束窗口交互 |
| 所有单元已绑定 | 大屏所有 SCREEN_CELL 的 `device_id` 非 NULL，大屏创建时即校验，存在未绑定单元时不允许创建大屏 |

### 7.2 事务保证

使用 `@Transactional` 保证：
- 创建大屏时 SCREEN 和 SCREEN_CELL 写入的原子性
- 删除大屏时级联删除的原子性
